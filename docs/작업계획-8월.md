## 1. 순서를 이렇게 잡은 이유

네 가지를 번호순으로 하면 안 된다. 두 가지 제약이 순서를 정한다.

**첫째, 4번(모델)에는 사람이 붙어 있지 않아도 되는 긴 대기시간이 있다.** URFD·MCF 242개
영상의 특징 추출은 몇 십 분에서 몇 시간이 걸리는데 그동안 할 일이 없다. 그러니
**오늘 가장 먼저 걸어두고, 도는 동안 UI 작업을 한다.**

**둘째, 1번(영상 연결)은 2번(공간 명칭)에 의존한다.** 지금 코드는 샘플 영상을
`bedroom.mp4` / `living.mp4` 로 부른다. 새 명칭에 맞춰 파일명과 매핑을 정한 뒤에
영상을 넣어야 두 번 일하지 않는다.

그래서 실제 실행 순서는 **4(착수만) → 3 → 2 → 1 → 4(마무리)** 다.

### 지금 상태에서 발견한 것 두 가지

**실험 A의 결론이 배포에 반영되지 않았다.** `docs/모델-v6-실험.md` 는 W75(3초 창)

#### DB 스키마

`users.role` 의 CHECK 제약이 `('senior','guardian')` 으로 박혀 있다. SQLite는 CHECK를
ALTER로 못 바꾸므로 **스키마를 고치고 `daon.db` 를 지운 뒤 재시드**한다. 데모 데이터뿐이라
마이그레이션을 쓸 이유가 없다.

```sql
-- users.role: CHECK (role IN ('admin')) — 향후 확장 여지만 남기고 분기는 전부 제거
CREATE TABLE cameras (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    admin_id INTEGER NOT NULL REFERENCES users(id),
    name TEXT NOT NULL,              -- '공용 라운지 1번 카메라'
    location TEXT NOT NULL,          -- '세대 내부' | '공용 라운지' | '복도'
    device_key TEXT UNIQUE,          -- 파이프라인이 자기를 식별하는 키
    status TEXT NOT NULL DEFAULT 'offline',
    paired_at TEXT
);
CREATE TABLE residents (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    admin_id INTEGER NOT NULL REFERENCES users(id),
    name TEXT NOT NULL,
    age INTEGER,
    address TEXT NOT NULL,           -- 119 신고 지원용
    phone TEXT,
    room TEXT,                       -- 호실
    note TEXT
);
-- surveys 테이블은 DROP (죽은 코드)
```

#### "나의 카메라" (블루투스 방식 UX)

블루투스 페어링처럼 보이게 하되, 실제로는 **서버에 등록된 파이프라인을 목록으로
보여주는 것**이다. 흐름은 이렇게 잡는다.

```
[카메라 추가] 누름
   → "주변 카메라를 찾는 중…" (스캔 애니메이션 2~3초)
   → 발견된 목록: 실제 연결된 파이프라인 + 미등록 기기
   → 선택 → 이름·설치 공간 입력 → 연결 완료
   → 목록에 온라인/오프라인 상태 뱃지
```

`main.py --live-url` 로 붙는 파이프라인에 `--device-key` 를 넘겨 자기를 등록하게 하면,
실제로 켜져 있는 카메라 1대는 진짜로 목록에 뜬다. 나머지는 시연용 더미로 채운다.
**이 부분은 시연에서 가장 눈에 띄는 화면이므로 공을 들일 값어치가 있다.**

#### 어르신 정보와 119 신고 지원


**주의 두 가지.**

첫째, **영상이 Docker 이미지에 그대로 들어간다.** `.dockerignore` 에 데이터셋은 빠져
있지만 `public/` 은 빌드 산출물이라 포함된다. 배포 인스턴스가 1~2GB이므로 영상은
**720p·H.264·10~20MB 이하**로 줄여서 넣는다.

```bash
ffmpeg -i 원본.mp4 -vf scale=-2:720 -c:v libx264 -crf 28 -preset slow -an demo.mp4
ffmpeg -i demo.mp4 -vframes 1 -q:v 3 demo.jpg     # 포스터
```

둘째, 오디오는 뺀다(`-an`). 시연장에서 소리가 나면 곤란하고 용량만 먹는다.

## 4. 보류 — 폰으로 실시간 영상 보기

본 작업이 끝나고 8/15~16에 여유가 있으면 진행한다. 같은 와이파이 기준이면 구조는
간단하지만 **함정이 세 개** 있어서 반나절로는 안 끝날 수 있다. 요약만 남겨둔다.

```bash
python3 -m uvicorn webservice.app:app --host 0.0.0.0 --port 8000   # 기본값 127.0.0.1 이면 폰에서 안 보임
ipconfig getifaddr en0                                             # 노트북 LAN IP
# 폰 브라우저에서 http://<그 IP>:8000
```

- **폰을 카메라로 쓰려면 HTTPS가 필요하다.** `getUserMedia` 는 HTTPS 또는 localhost
  에서만 동작한다. **뷰어 용도면 HTTP로 충분**하다
- **전시장 와이파이가 기기 간 통신을 막는 경우가 흔하다**(client isolation). 노트북
  핫스팟을 대비책으로 준비하고 리허설 때 현장에서 확인
- **macOS 방화벽**에서 파이썬 수신 연결을 허용해야 한다
